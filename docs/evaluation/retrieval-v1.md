Generated by `pnpm retrieval:benchmark` at 2026-10-01T20:43:58+00:00. Machine-readable copy: [retrieval-v1.json](retrieval-v1.json). Every number below was measured by that command on the machine described at the end.

- Embeddings: `trajectory-gnn-transformer-v1`, 14,108 plays, 128-d, L2-normalised (frozen Phase 3 export, sha256 `c54181e8342c`).
- Dataset `nfl_bdb_2026_analytics@full-91dc5311e8c7`, split `temporal-weeks-v1-b39c53db8a01` (train 10,862, validation 1,687, test 1,559).
- Retrieval corpus: every stored play of the model version (all splits); the query play is excluded.
- PostgreSQL 18.6 (Debian 18.6-1.pgdg13+2), pgvector 0.8.7; index `play_embeddings_embedding_hnsw` (HNSW, `vector_cosine_ops`, m = 16, ef_construction = 64); iterative scan `relaxed_order`, `hnsw.max_scan_tuples` = 20000.
- Ground truth: exact search (sequential scan, ORDER BY cosine distance, play_id), verified against NumPy. 600 query plays: 200 plays per split with the smallest sha256('retrieval-benchmark-v1:<play_id>').

## Exact search is correct

Exact pgvector search was compared with an independent NumPy brute force (float64 cosine over the exported float32 vectors) for 120 query plays × 9 filter scenarios = 1080 searches at k = 10: **1080 of 1080 returned the same plays in the same order**; the largest distance difference was 2.8e-07. Stored vectors equal the export bit for bit (max abs difference 0.0), and the query play never appeared in its own results.

**Served default: `ef_search` = 40**. Rule: keep pgvector's default (40) if its unfiltered mean recall@10 >= 0.99; otherwise the smallest grid value that meets it. Recall@10 1.0000, statement 1.21 / 2.61 / 5.96 ms. The lowest per-query recall@10 at this setting was 1.0 (play `2023112602-80`).

HNSW reduced database retrieval latency on this corpus: the nearest-neighbour statement took 1.2 ms against 4.6 ms for the exact scan at the median, and 2.6 against 5.2 ms at p95. The practical benefit is modest at 14,108 vectors: the exact scan is already a few milliseconds, the saving is a small part of a whole request (see endpoints), p99 tails on this loaded machine are noisy, and under very selective filters the advantage disappears (see filtered search). The index matters more as the corpus grows.

## What the scores look like

Across the 600 sampled queries the nearest neighbour's cosine similarity has median 0.986 (minimum 0.927, maximum 0.997). Random play pairs in the same space average about 0.44 with a wide spread (the space is anisotropic; see the cosine reference stored with the embeddings). Absolute cosine values are therefore close to 1 for most neighbours and are not probabilities; the product leads with rank and evidence.
